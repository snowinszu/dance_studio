# 数据备份与恢复

晓·乐舞艺术空间的**所有业务数据**（学员、考勤、课程、库存）都存在一个 SQLite 数据库文件里。
本文说明备份怎么产生、放在哪，以及万一数据库损坏时怎么用备份恢复。

---

## 数据库文件在哪

主数据库文件名固定为 `dance-studio.db`，位于系统的「用户数据目录」下：

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\晓·乐舞艺术空间\dance-studio.db` |
| macOS | `~/Library/Application Support/晓·乐舞艺术空间/dance-studio.db` |
| Linux | `~/.config/晓·乐舞艺术空间/dance-studio.db` |

运行时同目录下可能还有 `dance-studio.db-wal` 和 `dance-studio.db-shm` 两个伴生文件，
它们是 SQLite 的预写日志，属于正常现象。

> 开发环境下如果设置了环境变量 `STUDIO_DB_PATH`，数据库会改到该路径，备份目录也随之在其
> 同级的 `backups/` 下。

---

## 备份目录

备份统一放在用户数据目录下的 `backups/` 子目录里，例如
`~/Library/Application Support/晓·乐舞艺术空间/backups/`。

在应用里点 **设置 → 数据备份 → 打开备份目录** 可直接打开这个文件夹。

### 文件名含义

```
dance-studio-20260830-190705.db                 ← 日常快照，2026-08-30 19:07:05 生成
dance-studio-20260830-183012-premigrate-v6.db   ← 「迁移前」，升级到结构 v6 之前留的
dance-studio-20260830-201500-pre-restore.db     ← 「恢复前」，某次恢复操作前给当时数据留的底
```

- **日常快照**：每个自然日应用首次启动时自动生成一份；也可以在设置页手动点「立即备份」随时生成。
- **迁移前**：每次应用要升级数据库结构之前自动生成一份，是升级出问题时的旧结构还原点。
- **恢复前**：每次执行「恢复」之前，自动给当时的数据留一份底——恢复错了还能再退回来。

每份快照生成后都会立即做一次 `PRAGMA quick_check` 完整性自检，校验不过的不会留下。
所有快照都是**自包含的单文件**，可以直接用任何 SQLite 工具打开。

### 保留策略

- 日常快照只保留**最近 20 份**，更早的自动删除。
- 「迁移前」和「恢复前」快照**永久保留**，不受数量限制。

### 另存到 U 盘 / 网盘

本机磁盘如果损坏，本机的备份也会一起丢。设置页的 **另存一份到…** 会在生成一份日常快照的
同时，把它额外复制到你选择的目录（比如 U 盘或网盘同步文件夹）。建议定期这样做一份异地副本。

## 恢复（应用内，推荐）

设置页 → 数据备份：

- **备份列表某行右侧「恢复」** —— 用那份快照恢复。
- **「从文件恢复…」** —— 选任意 `.db` 文件恢复（比如从 U 盘 / 网盘拿回来的副本）。

点下去之后：

1. 应用先校验那份文件是不是完好的、属于本系统的数据库，不是就直接拒绝。
2. 弹确认框。确认后，**先自动给当前数据备份一份**（进备份列表，类型标「恢复前」）。
3. 应用**自动重启**，在下次启动最早期把数据库换成你选的那份，然后正常打开。
4. 如果那份快照的结构版本比当前程序旧，启动时会自动升级到最新版（升级前照例再留一份「迁移前」）。

> 恢复是**整库替换**：会回到那份快照的状态，快照之后录入的数据都会被丢弃（但已存进「恢复前」
> 快照里，可以再恢复回去）。

## 手动恢复（兜底：应用打不开时）

应用能打开就用上面的应用内恢复。只有在应用起不来、连设置页都进不去时，才手动换文件：

1. **完全退出应用。** 确认没有任何一个窗口还开着。
2. **找到备份目录。** 按本文开头的路径表找到用户数据目录下的 `backups/`。
3. **挑选要恢复到的快照。** 文件名里的日期时间越近越新；带 `-premigrate-v` 的是某次升级前留的。
4. **给当前数据库留底。** 把用户数据目录下的 `dance-studio.db` 改名，例如
   `dance-studio.db.bak-手动恢复前`。这样万一恢复的快照也不对，还能退回来。
5. **放入快照。** 把第 3 步选中的快照文件**复制**到用户数据目录，并改名为 `dance-studio.db`。
6. **清掉旧的伴生文件。** 删除同目录下的 `dance-studio.db-wal` 和 `dance-studio.db-shm`（如果有）。
   这两个文件属于「上一个数据库」，留着会和新放进来的快照对不上。
7. **重新打开应用。** 结构版本偏旧的话，启动时会自动升级到最新版。

### 常见问题

**Q：双击快照文件能直接打开应用吗？**
不能。用应用内「恢复」，或按手动步骤替换掉 `dance-studio.db`。

**Q：恢复错了想退回去？**
每次恢复前都自动留了一份「恢复前」快照，在备份列表里找到它、再「恢复」一次即可。

**Q：快照打不开 / 应用报「数据库打开失败」？**
换一份更早的快照重试。日常快照有多份，「迁移前」「恢复前」也都在，挑相邻的一份通常就能用。

**Q：只想回退数据库结构版本（不换数据）怎么办？**
本工具不支持结构降级。正确做法是恢复对应版本的 `-premigrate-vN` 快照——它本身就是那个旧结构 +
当时的数据。
